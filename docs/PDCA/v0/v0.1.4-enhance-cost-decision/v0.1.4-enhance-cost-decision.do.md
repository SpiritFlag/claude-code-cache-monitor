## 2. 구현 결정

| # | 무엇 | 어떻게 | 이유 | 관련 |
|---|---|---|---|---|
| 1 | `deferred_tools_delta.addedNames`에서 서버 이름 뽑는 규칙 | `mcp__<서버>__<툴>`을 `'__'`(이중 언더스코어)로 split해 앞 `mcp`와 뒤 툴 이름을 빼고 가운데를 다시 `'__'`로 합친다. 서버 · 툴 이름 내부의 단일 언더스코어는 split에 안 걸림 | design이 정확한 파싱 규칙을 안 줌. CC가 툴 이름을 지을 때 구분자로 이중 언더스코어만 쓴다고 보고 이걸로 서버 부분을 역산 | B-1, D-1 |
| 2 | sys 사다리의 key · project 칸이 "자기 자신"만 있어도 맞아버리는 문제 | `CAL.byKey` · `CAL.byProj`에 값을 `{sid, v}`로 저장하고, `resolveSys`가 median 낼 때 지금 세션의 sid를 빼고(`medianExcl`) 본다. `CAL.folder`는 기존 `CAL.sys`와 같은 뜻이라 자기 제외 없이 그대로 둔다 | design은 `resolveSys` 본문을 안 주고 뼈대만 줬다. 자기 제외가 없으면 세션 자신의 (미검증) warmStartTotal이 항상 자기 key 칸에 이미 들어있어 `cold-folder`/`warm-folder`/`*-project` 칸이 전혀 발동하지 않는 사다리가 된다 — 검증용 `mcp-config-warm` 픽스처(세션 하나뿐)가 `warm-folder`를 내야 하는데 이 장치 없이는 `warm-key`가 먼저 걸림 | B-1, D-6, D-7 |
| 3 | `cfgKey === ''`(구성 키를 못 만든) 세션을 **sys** 보정 재료에서만 뺀다 | `calibrate()`가 이런 세션을 `CAL.byKey` · `CAL.byProj` · `CAL.folder.cold` · `CAL.folder.warm`에는 안 넣고 `CAL.noCfgKey`만 올린다. 압축 재료(`summary` · `regrowth` · `rewrite` · `extra` · `postCtx`)는 MCP 구성과 무관해 cfgKey 유무와 상관없이 그대로 넣는다 | design 본문은 "모든 세션을 훑어" 넣는다고 썼지만, 같은 §3 B-1 검증문이 `mcp-config-none` 픽스처(구성 키 없음, 세션 하나뿐)에서 `sysSource === 'default'`를 요구한다. sys 계열만 빼야 그 단언을 만족하면서도 압축 재료의 기존 폴더 중앙값 집계(사이클 이전부터 있던 동작)를 안 건드린다 | B-1, B-3, D-5, D-6, plan 1.1의 R-3(참고) |
| 4 | `(projKey, cfgKey)` 맵 키 조합 방식 | design 주석은 `${projKey}\u0000${cfgKey}`를 예시로 들었지만 구현은 `JSON.stringify([projKey, cfgKey])`를 썼다 | 이 키는 내부 Map 키일 뿐 밖으로 노출되지 않아 정확한 구분자가 계약이 아니라고 봤다. 이스케이프 문자를 코드에 직접 타이핑하다 리터럴 NUL 바이트가 파일에 박히는 사고를 두 번 겪어(§5 참고), 프로젝트 경로에 어떤 문자가 와도 충돌이 없고 로그에서도 읽을 수 있는 `JSON.stringify` 조합으로 바꿨다 | B-1, D-5 |
| 5 | `s.compactSamples`에 담는 값 | design §2.2 인터페이스가 준 그대로 `{ rewrite, extra, ctx: total }` — 브레이크 판정에서 이미 계산한 지역변수 `rewrite`(캐시 밀림으로 다시 쓴 토큰수) · `extra`(그 실비)를 그대로 쓴다 | design §3 B-3 검증문은 "압축 직후 호출의 `curCw` · `extra` · `ctx`가 그대로 나온다"고 §2.2와 다르게 표현하는데, `curCw`(그 호출의 `cache_creation_input_tokens`)는 `rewrite` 변수와 값이 다를 수 있다(브레이크의 `rewrite`는 `min(prevCached-cr, cw+in)`로 캡이 걸림). §2.2의 실제 인터페이스 코드를 더 신뢰해 `rewrite`를 썼고, 테스트 픽스처는 캡이 `cw+in` 쪽에서 걸리도록 수치를 골라 두 표현이 같은 값을 가리키게 했다 | B-3, D-9 |
| 6 | `CAL.warmSys`(폴더 웜 중앙값)를 계산은 하되 화면엔 안 띄운다 | `calibrate()`에서 `CAL.warmSys = median(folder.warm)`까지만 채우고, `index.html` `calNote()`에는 design이 명시한 세 항목(재작성 · 압축 후 컨텍스트 · 압축 실비)만 붙인다 | design §2.2의 D-5 절이 `CAL.warmSys` 필드를 나열하지만, B-4의 `calNote()` 수정 지시문은 이 필드를 언급하지 않는다. 필드 존재는 인터페이스대로 맞추되 안 쓰는 화면 요소를 새로 만들지는 않았다 | B-3, D-5, D-9 |

### 1.2 갈림길 상세

#### D-4 프로젝트 키를 어디서 뽑나

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | `path.relative(ROOT, 파일경로)`의 디렉터리 부분 첫 세그먼트. 없으면 `''` | 실측 아카이브는 세션 jsonl이 `ROOT` 바로 아래에 평평하게 있어 전부 `''` 한 덩어리가 된다. 이 데이터로는 프로젝트가 갈리는 동작을 검증할 수 없다 |
| b | `s.cwd`를 소문자화하고 경로 구분자를 통일해서 쓴다 | 아카이브의 cwd는 `c:\…\CogMoUp-Fishing` 64건 · `C:\…` 17건 · `…\Assets\Games\Fishing` 2건 세 표기다. 대소문자는 정규화로 합쳐지지만 하위 폴더에서 연 세션은 다른 프로젝트가 되어 표본이 쪼개진다 |
| c | a를 쓰되 비면 b로 폴백 | 아카이브에서 a가 항상 `''`이므로 곧바로 b로 떨어져 b의 하위 폴더 문제를 그대로 받는다. 코드는 둘 다 |

**선택**: a (사용자 확정 2026-09-05). 실사용 `~/.claude/projects/<인코딩된 cwd>/`가 정확히 이 세그먼트이고 CC가 이미 cwd 단위로 폴더를 나눠 두었다. 아카이브가 `''` 하나로 묶이는 것은 손실이 아니라 사실과 일치한다(F-4: 이 아카이브는 프로젝트 하나다).

#### D-8 압축 비용 식

현재 `postCtx = min(total, sysTokens + CAL.summary)` 하나가 두 자리에 쓰인다. `perCallAfter`(압축 후 호출당 캐시 **읽기**)와 `compactionCost`의 **쓰기** 항이다. 실측은 두 값이 다르고, 압축 전 크기와도 다르다. 압축 브레이크 16건의 압축 전 컨텍스트는 207,976~853,098으로 4배 넘게 벌어지는데 압축 후는 72,549~101,214(중앙값 87,852)로 수렴한다. 압축은 죽은 무게만 걷어내는 것이 아니라 살아있는 부분까지 요약으로 갈아치우는 동작이다.

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 재료 셋을 폴더 실측 중앙값으로. 읽기 기준 = 압축 직후 컨텍스트 중앙값, 쓰기 기준 = 압축 직후 재작성 중앙값, 요약 출력 = `postTokens` 중앙값 | 폴더마다 · 사용자마다 값이 흔들려 같은 화면의 같은 숫자를 설명할 기준점이 없다. 압축 표본이 없는 폴더는 기본값으로 떨어져 값이 크게 튄다 |
| b | 재료 둘. `postCtx` 실측 중앙값을 읽기·쓰기 두 자리에 그대로 쓴다 | a의 흔들림에 더해, 압축을 넘어 캐시에 남는 프리픽스 36,792를 "새로 쓴다"고 세어 sonnet 기준 약 $0.147 과대 |
| c | 세션별. 압축 후를 `total − dead`로 보고 그만큼을 한 번 다시 쓰는 비용으로 잡는다 | 실측과 반대다. ctx 700k · dead 30% 세션의 `total − dead`는 490k인데 실제 압축 후는 87k라 5.6배 과대이고, sonnet 기준 $1.42~$2.28로 현재 $1.152보다 오히려 비싸져 P1-2의 "더 적극 권유"와 반대로 간다 |
| d | 고정 상수 셋. 요약 20,000 · 압축 직후 재작성 55,000 · 그 후 다시 읽기 60,000 | 폴더별 차이를 반영하지 못한다. 다만 실측이 압축 후 크기가 압축 전 크기와 무관하게 수렴함을 보였으므로 반영할 폴더별 차이가 애초에 크지 않다 |

**선택**: d (사용자 확정 2026-09-05). 압축 권유는 "할까 말까"의 판단이고 이 폴더의 순이득이 $2~11 범위라 비용이 $0.66이든 $0.80이든 결론이 바뀌지 않는다. 그 정밀도를 얻는 대가로 기준점이 폴더·사용자마다 달라지면 숫자를 설명할 수 없다. 실측 재료는 버리지 않고 D-9대로 표시에만 쓴다.

```
COMPACT = { summary: 20000, rewrite: 55000, regrowth: 60000 }
postCtx        = min(total, sysTokens + COMPACT.summary)          // 읽기 기준. sysTokens는 세션별 실측 사다리
perCallAfter   = postCtx * p.in * p.read / 1e6
compactionCost = (COMPACT.summary * p.out + COMPACT.rewrite * p.in * 2 + COMPACT.regrowth * p.in * 2) / 1e6
```

모델별 압축 비용은 sonnet $0.660 · opus $1.650 · fable-5-1 $3.300 · haiku $0.330으로 고정된다(현재 sonnet $1.152).

#### D-10 압축 권유 톤 강화 임계

FR-5의 "임계값을 넘으면 문구 톤을 강화한다". 현재 추천선은 이미 `saving > compactionCost`다.

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 절대액. 순이득 ≥ $1.00 | 모델 단가에 둔감하다. haiku 세션은 컨텍스트가 아무리 커도 이 선을 넘기 어렵고, opus 세션은 이득이 얇아도 넘는다 |
| b | 비율. 순이득 ≥ 압축 실비 × 3 | 절대액이 푼돈인 작은 세션에서도 배수만 크면 강한 톤이 나온다 |

**선택**: b (사용자 확정 2026-09-05). 추천선(`saving > compactionCost`, 1배)과 톤 강화선이 같은 척도 위 배수로 놓여 둘의 관계가 코드와 문구에서 그대로 읽히고, 모델 단가가 달라도 뜻이 유지된다. 잠정치이며 조정 관찰 항목을 백로그로 만든다(plan §7 (c)).

## 5. 진행 로그

### 세션 1 (2026-09-05)

- 시작: B-1(axis-server) 맡음. design 확정본(1.0)과 RULE.md 검증 수단 읽음. scope 인자 없어 첫 미착수 배치의 모듈(axis-server = B-1 단독) 전체가 이번 세션 범위.
- 종료: B-1 구현·검증 완료(`activeAt` 헬퍼, `lastA`·`promptMarks` 필드, 시리즈/브레이크 `a`, `detail`의 `prompts`, 픽스처 3개 + 테스트 2파일). `node --test` 27 passed. 사용자 요청으로 B-1에서 세션 종료 — B-2~B-6은 다음 세션. 다음 세션 주의점: B-2부터는 육안 검증(브라우저)이 필요하니 세션 시작할 때 서버 기동 계획을 먼저 잡을 것.

### 세션 2 (2026-09-05)

- 시작: B-2(axis-chart) 맡음. `index.html`의 `drawChart`를 `t` 축에서 `a`(활성 누적 ms) 축으로 교체.
- B-2 도중 q-1 발생(스무딩 여부) — 질문 파일 만들고 멈춤. 사용자가 a(직선 유지, design 그대로)로 답해 design 변경 없이 종결.
- B-2 사용자 육안 확인("B-2 승인") 받고 검증 완료 처리, 확인용 서버(포트 7799) 종료. B-3(break-palette) 착수.
- B-3 구현(`CAUSE_GROUPS`·`causeGroup`·`causeColor`·`HABITS`·`FREE_CAUSES` 파생, `.c-*` 삭제, `breakTable` 인라인 색, 빨간점 삭제, 범례를 drawChart 끝에서 매번 재구성). 같은 서버(포트 7799)로 육안 검증 중 q-2 발생(색 스왑) — 반영 후 사용자 확인 받아 B-3 검증 완료.
- 범위 밖 발견(다음 사이클 후보): 그래프 맨 위 윤곽선(총 컨텍스트 라인)이 호출마다 그 호출을 처리한 모델(`col[b.m]`)로 색이 바뀌어 세션 안에서 모델이 여러 번 바뀌면 선 색이 구간마다 달라 보임. plan이 "모델별 선 색(`col`) — 그대로 둔다"고 이번 사이클 범위 밖으로 이미 명시해뒀고, 사용자도 화면 보고서야 원인을 알았다며 다음 사이클로 미루기로 함. `index.html`의 `drawChart` 중 `ctx.strokeStyle = col[b.m] || '#ccc';` 부분.

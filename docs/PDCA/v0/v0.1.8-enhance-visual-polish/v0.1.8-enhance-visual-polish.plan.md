## 1. 목적

대시보드 첫 화면의 보이는 것 세 갈래를 손본다. 셋 다 `index.html` 하나만 건드리고 서버는 손대지 않는다 — 재료(구성 토큰 `comp` · 시리즈 점의 모델 `m`)가 이미 와이어에 있다. 첫째는 ec0ab17d의 "상단 타일 4개의 내부 레이아웃이 정돈되지 않았다. 요소 정렬이 안 맞고 한쪽으로 치우치며 세로로 늘어져서 보기 좋지 않다"이고, 배치(1x4 또는 2x2)와 타일 안 배치를 Claude Design 시안으로 만들어 사용자가 고른 것을 옮긴다. 요소를 더하고 빼는 것도 들어가되 무엇을 더하고 뺄지는 사용자 판단이다. 둘째는 a41629bd의 "상단 context 바가 지금은 통째로 파란색 한 색이라, 그 컨텍스트가 무엇으로 채워져 있는지 위쪽만 봐서는 알 수 없다"이고, 아래쪽 Context composition의 색 체계(`COMP`)를 그대로 올려 1M 기준 절대량만큼 칠하고 범례를 붙인다. 굵기와 모양은 그대로다. 셋째는 829998a7의 "총 컨텍스트 선의 색이 그 호출을 처리한 모델을 따라간다. 한 세션 안에서 모델을 여러 번 바꾸면 선 색이 구간마다 달라져, 모델 구분이 아니라 선이 끊긴 것처럼 보인다"이고, 이것은 직전 v0.1.7 report §3.4가 화면을 보고 발견해 §7 첫 후보로 올린 건이다. v0.1.7이 원인 색을 `CAUSE_GROUPS` 하나로 묶은 것과 같은 결로 모델 색도 한 곳에서 나오게 하되, 선 색으로 모델을 나타내는 방식 자체를 유지할지가 갈림길이다. 앞의 두 건은 사용자가 2026-09-06에 직접 등록했고 v0.1.7 산출이 아니다. 사용자가 2026-09-06 이 세 건을 범위로 지정했다.

## 2. 범위

### 2.1 포함 (3건, 확장 금지)

순서는 #1 → #2 → #3이다. #1과 #2는 재료가 확정돼 있어 코드만 바꾸면 되고 각각 작다. #3은 시안을 만들어 사용자가 고르는 반복이 들어가 셋 중 가장 길고 결과를 미리 알 수 없다. #3의 시안은 Context 타일 안에 #1의 색 바와 범례가 들어간 상태를 그려야 하므로 #1이 먼저다. #2는 상단 타일 밖(그래프 카드)이라 #3과 독립이다(질문 1). 크기는 #1 S · #2 S · #3 M이다.

## 질문

1. 순서. §2.1은 #1 색 바 → #2 선 색 → #3 타일 배치를 추천한다. #3의 시안이 #1의 결과(색 바 + 범례)를 담고 그려져야 해서다. 반대로 #3을 먼저 하면 시안이 지금의 단색 바로 그려지고 #1이 나중에 그 자리에 들어간다. 어느 쪽인가.
2. 선 색 방향. (가) 윤곽선을 한 색으로 긋고 모델 이력은 지금 있는 모델 바꾸기 점선과 Cache breaks 표에 맡긴다. `col`은 지운다. (나) 윤곽선은 한 색으로 긋고, x축 바닥에 모델별 색 띠를 얇게 깔고 범례에 모델 항목을 더한다. `col`은 상수로 승격한다. (다) 구간별 색은 그대로 두고 범례에 모델 항목만 더해 "끊김이 아니라 모델"임을 알린다. 추천은 (가)다 — F-7대로 이력은 이미 두 곳에 있고, 실사용에서 모델 바꾸기가 드물어(F-6) 띠가 대부분 한 색이 된다.
3. 상단 바 범례의 항목. (가) 하단 `compBar`처럼 0이 아닌 층만. (나) 여덟 층 모두. 추천은 (가)다 — 상단 타일은 폭이 좁고, 이미지 · 압축 요약은 대부분 0이다(F-3의 관측에서 압축 요약이 0이 아닌 세션은 v0.1.7 F-10 기준 아카이브 14/41 · 실사용 1/23).
4. 타일 요소 가감. 시안을 만들기 전에 미리 정해 둘 후보가 있는가(예: Context 타일의 `cacheR · cacheW · compacts` 줄, Cost 타일의 out · think · calls 세 칸, 캐릭터 타일의 모델 배지). 없으면 시안 두 안(1x4 · 2x2)을 지금 요소 그대로 그리고, 그것을 보며 정한다.

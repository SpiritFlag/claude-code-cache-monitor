## 1. 결과

범위 세 건을 모두 마쳤다. 상단 Context 타일의 단색 바가 여덟 층 색 바와 여덟 항목 범례로 바뀌면서 하단 Context composition 카드가 통째로 사라졌고, 그래프의 총 컨텍스트 윤곽선은 모델별 구간 색을 버리고 한 색 한 path가 됐으며, 상단 네 타일은 카드마다 "상단 고정 · 남는 높이를 먹는 가운데 · 바닥 고정" 세 층 구조를 갖게 돼 2x2로 접힐 때 카드 아래가 비지 않는다. 타일 배치 자체(1x4 · 2x2 · 한 열)와 서버는 손대지 않았다. SC 판정은 Analysis §1 참조. 계획과 달라진 것은 셋이다 — 시안을 `design` 스킬 캔버스가 아니라 사용자가 직접 쓴 명세 문서로 만들었고(D-17), 그 명세가 추정 단서 줄의 자리를 D-8과 반대로 옮겼는데 문서에 반영되지 않아 close 감사에서 고쳤으며(Analysis I-1), 요소를 더하거나 빼지 않기로 했던 원칙에서 Cost 타일의 3칸 통계(out · think · calls) 하나만 사용자 결정으로 삭제됐다. `comp`가 없는 세션의 단색 한 층(SC-12)은 해당 세션이 아카이브에도 실사용에도 없어 이번에도 화면으로 보지 못했다.

## 5. 회고

### 5.1 Keep

- 색의 단일 출처를 늘린 것. 상단 바 · 상단 범례 · 그래프 스택 · 그래프 범례가 전부 `COMP` 배열 하나에서 색과 순서를 받는다. 덕분에 "바의 색이 그래프 범례와 같은가"(SC-10)를 화면 없이 코드만으로 판정할 수 있었고, 이는 v0.1.7이 `CAUSE_GROUPS`로 세운 방식이 두 사이클째 이득을 낸 것이다.
- 직전 사이클 Try 1(SC 하나에 조건 하나)을 지킨 것. SC를 스물두 개로 잘게 쪼갠 덕에 D-8이 뒤집혔을 때 SC-22가 여전히 성립한다는 판정과 "결정은 안 지켜졌다"는 판정을 서로 오염시키지 않고 따로 적을 수 있었다.
- 사용자가 시안을 캔버스 대신 글 명세로 직접 써서 제출한 것. 클래스 이름 · CSS 값 · 마크업 구조까지 적혀 있어 B-5가 해석 없이 옮길 수 있었고, 시안 반복이 한 번에 끝났다(D-18 미발동).
- 육안 검증용 서버(8181 · 8182)를 배치마다 띄우고 끝나면 종료해 do §3에 남긴 것. 상시 모니터 7777은 한 번도 건드리지 않았다.

### 5.2 Problem

- 사용자 제출 시안을 design과 대조한 q-3이 충돌 세 건 중 두 건(범례 열 수 · Cost 통계 삭제)만 잡고 D-8(추정 단서 줄의 자리)을 놓쳤다. 대조 기준을 design §2.2 요소 목록에 뒀는데, 그 목록은 요소의 **존재**만 적고 **순서**는 D-8이 따로 적고 있었기 때문이다. 결과적으로 결정 하나가 조용히 뒤집힌 채 두 커밋을 지났고 close 감사에서야 잡혔다.
- design §2.2가 같은 사실을 두 곳(코드 블록과 요소 목록 표)에 적어두고 있어 둘이 서로 어긋난 채로 남았다. 코드 블록은 단서 줄을 범례 뒤에 붙이고 요소 목록은 바 앞에 놓아, design 자체가 처음부터 자기모순이었다(Analysis I-1). 링 크기 180px도 같은 방식으로 오래됐다(I-2).
- 직전 사이클 Try 2(◆ 목록을 육안 검증 직전에 한 번에 제시)는 B-1에서 D-4 · D-7 · D-8 세 건을 한 번에 물어보는 데까지는 작동했지만, 질문 세 건(q-1 · q-2 · q-3)은 여전히 났다. 셋 다 ◆가 붙지 않은 결정이었다 — 화면을 봐야 정해지는 것은 색과 모양만이 아니라 "이 줄이 어느 타일 소유인가"까지였다.

### 5.3 Try

1. do가 사용자 제출 산출물이나 시안을 design과 대조할 때 §2.2 요소 목록만 보지 말고 design §1.1의 D-n을 처음부터 끝까지 훑어 충돌 목록을 만든 뒤 질문 파일에 올린다 — 이번에 놓친 D-8은 요소 목록에 없고 결정표에만 있었다.
2. do §2 구현 결정에 "design 결정을 뒤집은 것"과 "design이 정하지 않은 것을 정한 것"을 구분해 적고, 전자는 그 자리에서 design Version History 개정을 함께 남긴다 — 뒤집힘이 close 감사까지 살아남지 않게.
3. design §2.2에서 같은 사실을 코드 블록과 표에 두 번 적지 않는다. 코드 블록에 적었으면 표에는 항목 이름만 두고 값·순서·크기를 옮겨 적지 않는다.

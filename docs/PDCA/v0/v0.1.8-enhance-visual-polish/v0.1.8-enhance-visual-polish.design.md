### 1.2 갈림길 상세

#### D-3 얇은 층에 `min-width:1px`를 두나

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 두지 않는다. 폭은 정확히 `c[k]/1e6`이고, 1px 아래로 떨어지는 층은 바에서 안 보인다 | 실사용 280k 세션에서 `images`·`summary`처럼 작은 층이 바에서 사라진다. 바만 봐서는 그 층이 0인지 작은지 모른다 |
| b | 하단 막대처럼 `min-width:1px`를 준다. 0이 아닌 층은 모두 최소 1px로 보인다 | 0이 아닌 층 여덟 개가 모두 밀려나면 칠해진 총 폭이 최대 8px 커진다. 폭 270px 바에서 약 3%p이고, SC-8이 요구하는 "칠해진 총 폭 = `ctx/1M`"이 그만큼 어긋난다 |

**결정**: a (사용자 검수 2026-09-06). 질문 3 답 (나)로 범례가 여덟 층을 **전부** 보이게 됐으므로, 바에서 안 보이는 층의 토큰과 비율은 바로 아래 범례에서 그대로 읽힌다 — b가 지키려던 것을 범례가 이미 지킨다.
남는 것은 SC-8의 등식뿐이고, 그것을 깨면서까지 1px를 살릴 이유가 없다.

#### D-11 총 컨텍스트 윤곽선의 색

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | `#e6e8ee`(`--fg`와 같은 값). 여덟 색 스택 위 가장 밝은 흰빛 윤곽 | 프롬프트 마커 `PROMPT_COLOR #e6e9f0`와 사실상 같은 색이 된다. "중립 흰색 = 프롬프트 입력 시점"이라는 뜻이 흐려진다 |
| b | `#8b93a7`(`--dim`과 같은 값). 조용한 회색 윤곽 | 시스템 층 `#5b6270`, 브레이크포인트 이동 `#7c8598`과 같은 회색 계열이라 셋이 뒤섞인다. 스택 맨 위 경계선이 여덟 색 위에서 묻혀 절벽·톱니가 덜 읽힌다 |

**결정**: a (사용자 검수 2026-09-06). 총 컨텍스트 선은 이 그래프의 주인공이라 여덟 색 스택 어디 위에 얹혀도 늘 갈리는 밝기여야 하고, 그 조건을 만족하는 것은 흰빛뿐이다.
프롬프트 마커와의 겹침은 자리와 모양이 갈라준다 — 마커는 x축 바닥선 위의 반지름 3px 원이고 윤곽선은 스택 맨 위를 지나는 1.5px 선이라, 한 화면에서 서로를 오인할 자리가 없다.

### 2.2 인터페이스

```js
// --- 상단 Context 바 (COMP 옆에 둔다)
const CTX_WINDOW = 1e6;   // 바의 분모. 지금 인라인으로 쓰던 1e6을 이름으로 올린다

// 여덟 층 <i>. comp가 없으면 지금과 같은 단색 한 층. (D-2 · D-9)
// 반환: '.ctxbar'의 innerHTML
function ctxBarSegs(s) {
  const c = s.comp;
  if (!c) return `<i style="flex:none;width:${Math.min(100, s.ctx / CTX_WINDOW * 100)}%;background:var(--acc)"></i>`;
  return COMP.map(([k, label, col]) =>
    `<i style="flex:none;width:${100 * (c[k] || 0) / CTX_WINDOW}%;background:${col}" title="${label} ${fmtTok(c[k] || 0)}"></i>`).join('');
}

// 여덟 항목 범례 + 추정 단서 한 줄. comp가 없으면 빈 문자열. (D-5 · D-6 · D-8)
// 비율의 분모는 여덟 층의 합(≈ ctx)이지 CTX_WINDOW가 아니다.
function ctxLegend(s) {
  const c = s.comp; if (!c) return '';
  const total = COMP.reduce((n, [k]) => n + (c[k] || 0), 0) || 1;
  const rows = COMP.map(([k, label, col]) => {
    const v = c[k] || 0;
    const lbl = k === 'sys' ? `${label} · ${SYS_SRC[s.sysSource] || '추정'}` : label;
    return `<div class="cl-row${v ? '' : ' zero'}"><b style="background:${col}"></b>`
      + `<span class="cl-lb">${lbl}</span><em class="cl-tk">${fmtTok(v)}</em>`
      + `<em class="cl-pc">${Math.round(100 * v / total)}%</em></div>`;
  }).join('');
  return `<div class="complegend">${rows}</div>`
    + `<div class="cl-note">구성은 추정 — 문자수 비율을 실제 컨텍스트에 맞춰 보정</div>`;
}

// --- 그래프 (PROMPT_COLOR 옆에 둔다)
const LINE_COLOR = '#e6e8ee';   // 총 컨텍스트 윤곽선 · 모델과 무관한 한 색 (D-11 · D-12)
```

```js
// hasComp가 아닐 때의 채우기 — 사다리꼴 여러 개 대신 폴리곤 하나
const y0 = Y(0);
ctx.fillStyle = LINE_COLOR + '22'; ctx.beginPath(); ctx.moveTo(X(pts[0].a), y0);
for (const p of pts) ctx.lineTo(X(p.a), Y(p.ctx));
ctx.lineTo(X(pts[pts.length - 1].a), y0); ctx.closePath(); ctx.fill();

// 윤곽선 — 구간별 stroke 대신 한 path 한 번
ctx.lineWidth = 1.5; ctx.lineJoin = 'round'; ctx.strokeStyle = LINE_COLOR;
ctx.beginPath();
pts.forEach((p, i) => { const x = X(p.a), y = Y(p.ctx); i ? ctx.lineTo(x, y) : ctx.moveTo(x, y); });
ctx.stroke();
```

|---|---|

굵게 표시한 줄은 이번에 자리가 바뀌거나 새로 들어온 것이다(B-1, 질문 q1 답 반영) — 여덟 층 바·여덟 항목 범례·추정 단서 한 줄은 하단 Context composition 카드가 주던 것을 이어받았고, 모델 원칙 한 줄은 Context → Cost로, 조건부 compact 권유 줄은 Context → Cache TTL로 소유 타일이 바뀌었다. 화면 전체로는 가감이 없다.

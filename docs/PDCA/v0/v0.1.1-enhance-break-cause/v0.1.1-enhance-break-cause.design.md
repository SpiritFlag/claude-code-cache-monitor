### 1.2 갈림길 상세

#### D-1 판정 로직을 테스트·스크립트가 부르는 방법

SC-1·3·6·8이 모두 "픽스처(jsonl)를 넣고 나온 브레이크를 본다"이고 SC-9가 "스크립트 집계 = `/api/state` byCause"다. 필요한 것은 순수 분류 함수가 아니라 **jsonl 한 묶음을 먹여 판정 결과를 얻는 진입점**이다.

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | `server.js` 끝의 기동 블록(348~355행)을 `require.main === module` 가드로 감싸고 `module.exports = { reset, replay, snapshot, detail, sessions, files }`를 붙인다 | 모듈 수준 전역(`sessions`·`files`·`CAL`)이 남아 테스트가 매번 `reset()`을 불러야 한다. 파일이 계속 355행+로 크다 |
| b | 판정부를 `lib/break-cause.js`로 떼어 순수 함수로 만들고 `server.js`가 require한다 | 픽스처 기반 SC를 만족하려면 결국 파이프라인 진입점이 또 필요해 파일이 둘 늘고, 판정이 두 곳(분류 함수·호출부)으로 갈라져 R-5가 되살아난다 |

**추천**: a. 이 저장소는 의존성도 모듈 구조도 없는 두 파일짜리이고, 서버가 실제로 도는 코드 그대로를 테스트·스크립트가 부르는 것이 R-5(복제 어긋남)를 없애는 유일한 길이다.

#### D-2 픽스처를 만드는 방법

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | plan §3의 수치를 그대로 넣어 손으로 쓴 합성 jsonl. 레코드당 필드 10개 안팎 | 실제 트랜스크립트의 예상 못한 형태를 못 잡는다. 128ae4a7 실사례는 여전히 미확보(R-1) |
| b | 아카이브에서 필요한 필드만 남기는 축약 스크립트를 만들어 뽑는다 | 스크립트 자체가 범위 밖 산출물이고, 개인정보 제거 누락 위험(SC-10)을 스크립트 품질에 건다. 128ae4a7이 없어 정작 SC-6은 여전히 합성 |

**추천**: a. SC-1·6은 애초에 특정 수치를 노려 만드는 픽스처라 실데이터가 필요 없고, SC-10(개인정보 부재)은 손으로 쓴 쪽이 확실하다. 실데이터 검증은 SC-2·4·7·9·13이 아카이브로 따로 한다.

**판정부** — 216~235행 교체

```js
const prev = f.prev; const events = f.pending; f.pending = [];
if (prev) {
  const prevCached = prev.total - prev.in;             // 직전 호출이 캐시에 남긴 프리픽스
  const rewrite = Math.min(Math.max(0, prevCached - t.cr), t.cw + t.in);
  if (rewrite > 2000) {
    const gapMin = (ts - prev.ts) / 60000;
    const shrink = prev.cr - t.cr;                     // 캐시 읽기 감소분(음수 가능)
    const grew = total - prev.total;                   // 컨텍스트 증감(음수 가능)
    const prefixIntact = t.cr >= prev.cr;
    let cause;
    if (m.model !== prev.model) cause = 'model_switch';
    else if (events.includes('compact')) cause = 'compact';
    else if (gapMin > (s.ttlMin === 60 ? 60 : 5)) cause = 'ttl_expiry';
    else if (events.includes('resume')) cause = 'session_resume';
    else if (shrink > 0 && Math.abs(rewrite - shrink) <= BP_SHRINK_SLACK && rewrite < BP_MAX_REWRITE) cause = 'breakpoint_shift';
    else if (d.effort !== prev.effort) cause = 'effort_change';
    else { const p = events.find(e => e.startsWith('prefix:')); cause = p ? p.slice(7) : 'unexplained'; }
    const p = price(m.model); const mult = t.cw1h > 0 ? 2 : 1.25;
    const extra = rewrite * p.in * (mult - p.read) / 1e6;
    if (!FREE_CAUSES.has(cause)) s.breakCost += extra;
    const bc = s.byCause[cause] = s.byCause[cause] || { n: 0, rewrite: 0, extra: 0 }; bc.n++; bc.rewrite += rewrite; bc.extra += extra;
    if (!FREE_CAUSES.has(cause) && !f.isSub) { brokeNow = true; s.lastAvoidableBreakTs = ts; }
    s.breaks.push({ ts, cause, rewrite, extra, model: m.model, from: prev.model, effort: prev.effort + '→' + d.effort, sub: f.isSub, ctx: total,
      prevIn: prev.in, prevCr: prev.cr, prevTotal: prev.total, curIn: t.in, curCw: t.cw, curCr: t.cr,
      cw1h: t.cw1h, cw5m: t.cw5m, shrink, grew, gapMin, prefixIntact, events });
    if (s.breaks.length > 60) s.breaks.shift();
  }
}
f.prev = { total, in: t.in, cr: t.cr, model: m.model, ts, effort: d.effort };
```

**픽스처 규칙** (SC-10을 어기지 않기 위한 제약)

- assistant 레코드: `type` · `sessionId` · `uuid` · `timestamp` · `effort` · `message{ id, model, usage, content:[{type:'text',text:'x'}], stop_reason }`.
- `usage`: `input_tokens` · `cache_creation_input_tokens` · `cache_read_input_tokens` · `output_tokens` · `cache_creation{ ephemeral_1h_input_tokens, ephemeral_5m_input_tokens }`.
- user 레코드: `type` · `sessionId` · `uuid` · `timestamp` · `isMeta` · `message{ content }`. **`cwd`를 넣지 않는다.**
- `last-prompt` 레코드는 `{"type":"last-prompt","sessionId":…,"uuid":…,"timestamp":…}`까지만. **`lastPrompt` 필드를 넣지 않는다.** `file-history-snapshot`도 같다.
- 호출 간격은 60초 이내(기본 `ttlMin`이 5분이라 그 이상이면 `ttl_expiry`가 먼저 잡는다). 모델·effort는 픽스처 전체에서 동일하게 둔다.
- 파일 경로에 `subagents`가 들어가지 않으므로 전부 메인 세션으로 판정된다.

**scripts/diag-breaks.js**

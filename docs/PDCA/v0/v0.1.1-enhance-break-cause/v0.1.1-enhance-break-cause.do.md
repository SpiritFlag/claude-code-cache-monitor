## 2. 구현 결정

> Design이 정하지 않은 세부를 어떻게 했는지. 설계를 바꾸는 것이면 여기 쓰지 말고 질문 파일로.
> Design에 없는 테스트를 추가했으면 여기 이유를 적는다. Design이 지목하지 않은 기존 테스트를 고치는 건 여기 적을 수 없다(질문 파일). 불안정한 테스트를 발견하면 끄지 말고 여기 기록한다.

| # | 무엇 | 어떻게 | 이유 | 관련 |
|---|---|---|---|---|
| 1 | RULE.md의 `node --test test/`가 이 머신의 Node v24에서 디렉터리 인자를 모듈로 require하려다 `MODULE_NOT_FOUND`로 실패함(`node --test <파일>` 또는 인자 없는 `node --test`는 정상 동작하고 결과가 동일) | do §3 실행 로그에 인자 없는 `node --test`(test/ 하위 전체를 자동 탐색)로 기록한다 | RULE.md·design 어느 쪽도 바꾸지 않고 같은 파일들을 discover하는 동등한 호출로 대체. 검증 기준(통과/실패)에는 차이가 없다 | B-1 |

## 5. 진행 로그

> 세션마다 시작 · 종료 시 한 단락. 막힌 것, 다음 세션이 먼저 볼 것.

### 세션 1 (2026-09-05)

- 시작: B-1·B-2(모듈 `break-core`) 담당. design.md와 RULE.md를 읽음. server.js·index.html 현재 구조를 확인함(216~235행 판정부, 260~262행 readFile 초기화, 348~355행 기동 블록).
- 계속: 사용자가 "아카이브는 월요일(2026-09-07)에 온다, 개발은 미리 해야 한다"고 확인 — design R-1이 이미 예견한 상황이므로 질문 파일 없이 B-3(`resume-cause`)을 합성 픽스처로 마저 구현하고, 아카이브가 필요한 검증만 보류로 넘김.
- B-3 구현: `RESUME_RE`·`markerText` 추가, `case 'user'`에 마커 검출(`isMeta` + 정규식 + `markerSeen` uuid 중복 무시), 판정 체인에 `ttl_expiry` 다음·`effort_change` 이전 자리에 `session_resume` 삽입(D-7 순서), `readFile`의 두 초기화 지점(신규 생성·truncate 리셋)에 `markerSeen: new Set()` 추가. 픽스처 3종(`resume-array-marker`·`resume-noise`·`resume-dup-uuid`)과 `test/resume-cause.test.js` 작성, SC-3·FR-3 자동 테스트 통과.
- 계속: B-4(`shift-cause`)·B-5(`habits-ui`)까지 마저 구현. `BP_MAX_REWRITE`(20000)·`BP_SHRINK_SLACK`(3000)·`FREE_CAUSES`(compact·breakpoint_shift)를 추가하고 판정 체인에 `session_resume` 다음·`effort_change` 이전 자리로 `breakpoint_shift`를 끼워 넣었다(D-7). `breakCost`·`brokeNow` 집계를 `FREE_CAUSES` 기준으로 바꾸면서 index.html의 compactCost 수동 차감 두 줄(scoreCard·heroCard)을 단순화했다(D-9). `HABITS`에 "세션 재개" 행을, `habitsCard` 제외 안내 줄에 `breakpoint_shift` 합산을 추가했다.
- 계속: 사용자가 `test/fixtures` 화면에서 습관 순위표의 "세션 재개" 행·바뀐 제외 안내 줄을 2026-09-05에 육안 확인("3개 확인했음") — B-5를 검증 완료로 올림.
- 종료: B-1·B-5 검증 완료. B-2·B-3·B-4는 구현 완료로 남음 — 로직·자동 테스트(7개 전부 통과)와 SC-10(B-5)까지는 확인했으나, SC-9(B-2)·SC-2·SC-4(B-3)·SC-7·SC-12·SC-13(B-4)·SC-11의 정확한 "3건"(B-5)이 요구하는 실제 대상 `data/fishing/extract`(D-11) 아카이브가 이 머신에 없어 그 폴더 기준 최종 확인은 못 함. 다음 세션 주의점: (1) 2026-09-07(월) 아카이브가 들어오면 `node server.js --dir data/fishing/extract --port 7788`을 띄우고 `node scripts/diag-breaks.js --dir data/fishing/extract`·`node scripts/diag-shrink.js`·`curl /api/state`·`/api/detail`을 아카이브 기준으로 대조해 B-2·B-3·B-4를 검증 완료로 올리고, 습관표의 "세션 재개"가 정확히 3건인지(SC-11)까지 사용자 육안으로 재확인할 것 — 이때 SC-5(128ae4a7 원본)도 함께. (2) `node --test test/`는 이 머신 Node v24에서 디렉터리 인자를 못 받는다(§2 #1) — 인자 없는 `node --test`를 계속 쓸 것. (3) B-2~B-4가 전부 검증 완료가 되면 §1 전건이 검증 완료가 되므로 헤더 상태를 `완료`로 바꾸고 새 세션에서 `/pdca-close`로 넘어갈 것.

### 세션 2 (2026-09-05, close)

- close 게이트가 B-2·B-3·B-4의 `구현 완료`에서 막혀 한 번 멈췄다. 사용자가 아카이브를 기다리지 않고 지금 닫기로 결정해(§4 Q-1) 진행했다. 세션 1이 남긴 "다음 세션 주의점" (1)은 그대로 유효하며, 아카이브가 오면 이 사이클이 아니라 후속 사이클에서 report §3.1의 이월 항목으로 확인한다.

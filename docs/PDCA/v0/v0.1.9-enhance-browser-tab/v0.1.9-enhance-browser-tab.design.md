## 1. 결정

### 1.1 결정 지점

| ID | 결정 지점 | 갈림길 | 결정 |
|---|---|---|---|
| D-1 | 탭 코드를 `index.html` 어디에 두나 | 없음 | `<script>` 맨 끝, 세션 목록 접기 블록(`NAVKEY` ~ `resize` 핸들러) **뒤에** 한 덩어리로 둔다 — `LINES` · `clockSkew` · `state` · `$`를 모두 읽어야 하고, 앞쪽 렌더 함수들과 섞이지 않아야 do가 지울 자리를 한 번에 본다. `<head>`에는 `<link id="favicon">` 한 줄만 더한다 |

| D-3 | 어느 세션의 전이가 깜빡임을 켜나 | 있음 → §1.2 | (a) 탭 세션(`sessions[0]`)의 전이만 |

| D-6 | 깜빡임을 무엇으로 표현하나 | 없음 | 제목 앞에 `\u{1F514} `(종 이모지 + 공백)를 붙였다 뗐다 한다 — 탭은 제목의 **앞부분**만 보이므로 뒤에 붙는 TTL 꼬리(D-8)로는 깜빡임이 안 보인다. favicon은 건드리지 않는다: 아이콘은 이미 상태 그림이고, 깜빡이면 D-9의 배지와 뜻이 겹친다 |
| D-7 | 깜빡임의 박자와 멈춤 | 없음 | 박자를 `tick()`(1초)과 스냅샷 도착 **둘 다**에 건다(R-2) — 숨은 탭 타이머 제한(F-7)이 걸려도 15초 하트비트가 박자를 잇는다. 멈춤은 `visibilitychange`로 보이게 될 때와 `window` `focus`일 때이고, 멈추면 제목이 즉시 원래대로 돌아간다. 시간 제한을 두지 않는다 — 사용자가 볼 때까지 부르는 것이 목적이다(FR-5). 상태가 유지되는 동안 다시 켜지지 않는다(전이 순간에만 켠다, R-8) |
| D-8 | TTL 꼬리를 붙이는 조건 | 있음 → §1.2 | (a) 상태와 무관하게 TTL이 살아 있으면 붙인다 |
| D-9 | favicon을 어떻게 그리나 | 없음 | 상태가 무엇이든 항상 32×32 `<canvas>`에 그려 `toDataURL()`로 `<link>` href를 바꾼다. 배지 없는 상태도 같은 경로를 탄다 — 배지 유무로 축소 방식이 달라지면 같은 캐릭터가 두 가지 선명도로 보이고, 캔버스를 거쳐야 D-11의 확대 손잡이가 한 곳에서 먹는다. 합성이 던지면 `href = /img/<state>.png`로 떨어진다(FR-6). 크기가 32인 것은 탭 16px의 2배(고DPI)라서다 |
| D-10 | 캐릭터 원본 이미지를 언제 읽나 | 없음 | 처음 그 상태가 필요할 때 `new Image()`로 한 장씩 읽고 `Map`에 담아 재사용한다. 8장(약 880KB)을 미리 다 읽지 않는다. 아직 안 온 이미지면 이번 합성을 건너뛰고 `onload`에서 다시 부른다 — 서버가 `max-age=3600`을 붙이므로(F-2) 두 번째부터는 네트워크가 없다 |

| D-12 | 배지의 모양과 자리 | 없음 | 32px 캔버스 오른쪽 아래에 반지름 7px 원, 채움 `#ff5c5c`(`--bad`), 테두리 2px `#0f1115`(`--bg`) — 테두리가 없으면 캐릭터 몸통(크림색) 위에서 점의 경계가 뭉갠다. 오른쪽 **위**는 `character-spec.md`의 안테나·물음표가 있는 자리라 겹친다. 배지를 다는 상태는 `asking` · `broke` 둘뿐이다(FR-6) |
| D-13 | 알림 권한 버튼의 자리 | 있음 → §1.2 | (a) 세션 목록 헤더(`aside h1`)의 `#navbtn` 왼쪽 |
| D-14 | 버튼이 권한 상태를 보이는 방법(R-4) | 없음 | `Notification.permission` 세 값을 아이콘 + `title` 툴팁으로 그린다: `default` 종 + "데스크톱 알림 켜기", `granted` 종 + "데스크톱 알림 켜짐", `denied` 종에 사선 + "브라우저가 알림을 차단했다". `granted`가 아니면 `.off`로 흐리게 한다. `Notification`이 아예 없는 브라우저면 버튼을 `hidden`으로 감춘다 |
| D-15 | 알림의 내용과 클릭 동작 | 없음 | 제목은 `LINES.asking`, 본문은 그 세션의 `title`, 아이콘은 `/img/asking.png`, `tag`는 `cc-monitor:ask:<sessionId>` — 같은 세션의 알림이 쌓이지 않고 마지막 하나만 남는다. `onclick`은 `window.focus()` 뒤 `close()`다(FR-7). 알림을 띄우는 조건은 탭 세션의 `working` → `asking` 전이 **그리고** `document.hidden`이며, 권한이 `granted`가 아니면 조용히 아무것도 하지 않는다 |
| D-16 | 탭 제목에 세션 제목을 넣나(R-3) | 없음 | 넣지 않는다 — 탭 폭이 좁아 앞 열몇 자만 보이는데 세션 제목이 앞에 오면 대사가 밀려 SC-4가 깨지고, 뒤에 오면 어차피 안 보인다. 대신 알림 본문에 세션 제목을 넣고(D-15) 탭이 맨 위 세션을 따른다는 규칙을 README에 적는다(D-18) |
| D-17 | 갱신을 어느 타이머에 태우나 | 없음 | 새 `setInterval`을 만들지 않고 기존 `tick()`(1초) **첫 줄**에서 부른다(F-6). `tick()`은 `state`가 없거나 `selected` 세션이 없거나 `#ttl`이 없으면 곧바로 `return`하므로 반드시 그 세 검사보다 **앞**이어야 한다 — 뒤에 두면 세션이 없을 때(SC-13)와 초기 로딩 때 탭이 영영 안 갱신된다. 스냅샷이 올 때도 `es.onmessage` 끝에서 한 번 더 부른다 |
| D-18 | README 손볼 자리(FR-10) | 없음 | 6~13행 요약 목록의 "상태 8개짜리 캐릭터" 다음에 탭 한 줄을 넣고, `## 캐릭터 이미지 추가/교체`와 `## 숫자 읽을 때` 사이에 `## 브라우저 탭` 절을 새로 만든다. 절에 담는 것: 아이콘·제목이 **가장 최근 활동 세션**을 따른다는 것(왼쪽에서 고른 세션과 다를 수 있다, R-3), 제목 뒤 `mm:ss`가 TTL이라는 것, 일이 끝나거나 질문이 뜨거나 캐시가 깨지면 탭이 깜빡인다는 것, 알림은 세션 목록 헤더의 종 버튼을 눌러 켠다는 것 |

### 1.2 갈림길 상세

#### D-3 어느 세션의 전이가 깜빡임을 켜나

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 탭 세션(`sessions[0]`)의 전이만 본다. 뒤로 밀린 세션의 전이는 무시한다 | 두 세션을 동시에 돌릴 때, 맨 위가 아닌 세션이 일을 마치면 알려주지 않는다. 그 세션은 다음에 다시 맨 위로 올라올 때까지 조용하다 |
| b | 스냅샷 안 **모든** 세션의 전이를 본다. 어느 세션이 끝나도 깜빡인다 | 깜빡이는 제목이 그 세션 것이 아니다 — 탭 제목·아이콘은 `sessions[0]`인데(FR-1) 부른 이유는 다른 세션이라, 사용자가 클릭해 들어와도 왜 불렀는지 화면에 없다. 놓친 세션을 찾으려면 목록을 훑어야 한다 |

**결정**: a (사용자 검수 2026-09-06). 탭은 화면 하나짜리 채널이라 "보여주는 것"과 "부르는 것"이 같은 세션이어야 클릭이 답으로 이어진다 — b는 부름과 화면이 어긋나는 순간을 만든다.
그리고 실제로 놓치는 경우는 두 세션이 겹쳐 도는 동안뿐인데, 그때 뒤로 밀린 세션이 끝나면 대개 그 세션이 다시 `lastTs` 맨 위가 되어 곧바로 탭에 올라온다.

#### D-8 TTL 꼬리를 붙이는 조건

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 상태를 보지 않고 TTL이 안 만료면 늘 붙인다 | `working` 중에는 호출마다 `lastCallStart`가 갱신돼 숫자가 5:00 근처로 되돌아간다. 줄어들기만 하는 눈금을 기대한 사용자에게는 튀는 것처럼 보인다 |
| b | `working` · `asking` 중에는 빼고 나머지 상태에만 붙인다 | 상태가 바뀔 때마다 제목 뒤가 나타났다 사라진다. 일하는 중에 "지금 캐시가 얼마나 남았나"를 탭에서 볼 수 없다 |

**결정**: a (사용자 검수 2026-09-06). 되돌아가는 숫자는 오해가 아니라 사실이다 — 호출이 캐시를 실제로 갱신했다는 뜻이고, 카드의 TTL 링도 지금 똑같이 되돌아간다(F-6).
SC-5가 "캐시가 살아 있을 때"만 조건으로 걸고 상태를 나누지 않으므로, b는 SC 없는 규칙을 하나 더 만드는 쪽이다.

#### D-13 알림 권한 버튼의 자리

| 선택지 | 내용 | 대가 |
|---|---|---|
| a | 세션 목록 헤더 `aside h1`, `#navbtn` 왼쪽에 종 버튼 하나 | 헤더가 정적 마크업이라 한 번만 붙이면 되고 늘 보인다. 대신 접힘 모드(44px)에서는 버튼 두 개가 안 들어가 종을 숨겨야 하고, 접어 둔 사용자는 권한을 켤 자리를 못 찾는다 |
| b | 캐릭터 카드 안(모델 이름표 아래)에 종 버튼 | 탭이 보여주는 그 캐릭터 옆이라 뜻이 이어지고 접힘과 무관하다. 대신 `renderMain`이 다시 그릴 때마다 버튼이 새로 생겨 핸들러를 매번 다시 걸어야 하고, 세션이 없으면(SC-13) 카드 자체가 없어 버튼도 사라진다 |

**결정**: a (사용자 검수 2026-09-06). 권한 요청은 브라우저에 한 번 하고 끝나는 설정이라 데이터에 딸린 카드가 아니라 **틀**에 있어야 하고, `renderMain`을 타지 않아야 다시 그릴 때 권한 창이 얽힐 여지가 없다.
접힘 모드에서 못 찾는 문제는 실제로 한 번만 겪는 일이고, 펼치면 바로 보인다.

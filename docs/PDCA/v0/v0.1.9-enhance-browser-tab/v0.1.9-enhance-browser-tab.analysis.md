| ID | 발견 | 위치 | 처리 | 재검증 |
|---|---|---|---|---|
| I-1 | 깜빡임과 알림을 **켜는** 조건은 `document.hidden`만 보는데 **멈추는** 조건은 `visibilitychange`와 `window` `focus` 둘 다 본다. 이 비대칭 때문에 대시보드가 브라우저의 활성 탭인 채로 브라우저 창 자체가 뒤로 밀린 경우(에디터·터미널을 보고 있는 흔한 상황) `document.hidden`이 `false`라 일이 끝나도 깜빡이지 않고 알림도 뜨지 않는다. Plan의 SC-6·SC-12는 "다른 **탭**을 보는 중"으로만 쓰여 있어 SC 위반은 아니지만, "화면 밖에서 알려준다"는 FR-5·FR-7의 목적은 이 경우 달성되지 않는다 | `index.html:664` (`startBlink`), `index.html:690` (`notifyAsk`) | 이월 → report §3.4 — 고치려면 켜는 조건을 `document.hidden \|\| !document.hasFocus()`류로 바꿔야 하고 이는 D-7·D-15의 조건 자체를 개정하는 일이라 감사가 임의로 정할 것이 아니다 | 코드 대조로 판정했고 브라우저 실측은 하지 않았다 |

## 4. 감사 방법

- 직접 실행한 것: `node --test`(27건 통과, do 기록과 같은 수), `git diff develop -- server.js`(빈 출력), `git diff develop --stat`, `index.html`의 탭 모듈 전문(588–711행)과 `<head>`·`aside h1`·`es.onmessage`·`tick()` 대조 읽기, `server.js`의 스냅샷 필드(`lastCallStart`·`ttlMin`·`title`) 기본값 확인, README 13·135·141·150행 위치 확인, design §1.1 D-1 ~ D-18 전체와 코드 한 줄씩 대조.
- Do 기록을 신뢰한 것: SC-1 ~ SC-7, SC-9, SC-11 ~ SC-13, SC-15의 사용자 육안·서버 로그. 탭·favicon·깜빡임·알림은 브라우저 안에서만 관측되고 `index.html`을 여는 자동 테스트가 없어(F-10) 이 세션이 같은 관측을 다시 만들 수 없다. 대신 각 SC마다 해당 코드 경로를 읽어 do의 주장과 코드가 어긋나지 않는지를 대조했고 그 내용을 §1 "독립 재확인" 열에 적었다.
- 감사 범위 밖: 캐릭터 이미지 자체의 16px 판독성(SC-2는 사용자가 통과로 판정했고, do 세션 1에서 사용자가 남긴 "이미지는 나중에 바꾸긴 해야할듯" 코멘트는 report §3.4로 간다). Chrome·Edge 이외 브라우저(R-5, Plan §2.2 제외). 숨은 탭 5분 초과 시의 깜빡임 박자(R-2)는 do가 실측하지 못했고 이 세션도 실측하지 않았다.

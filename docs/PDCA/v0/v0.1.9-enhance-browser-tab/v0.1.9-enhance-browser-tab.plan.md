## 1. 목적

대시보드가 브라우저 탭 하나로 접혀 있을 때도 캐릭터의 상태가 보이게 한다. 사용자가 2026-09-06에 직접 지정한 주제이고 백로그 항목이 없다. 사용자의 문장은 "일단 현재 활성화된 세션의 캐릭터 상태를 가져와서 그에 맞게 다음 행동을 수행", "favicon을 캐릭터와 동일하게 바꾸기, 쉴때는 쉬는모습, 일할때는 일하는모습, 기존 이미지를 축소만 해서 일단 해보고, 안되면 전용 이미지를 뽑거나 할듯", "탭 제목을 말풍선이랑 동일하게 하기, '작업중' 등.., 'cc-monitor' 이거 안보여도 됨", "working→idle, working→question과 같이 일하다가 일을 마쳤을때 탭이 깜빡거려서 클릭 유도하는 효과 주기"다. 지금 탭은 제목이 `cc-monitor` 고정이고 favicon이 없어서, 클로드가 일을 끝냈는지 질문을 띄웠는지는 탭을 클릭해 들어와야만 안다. 캐릭터 카드(v0.1.5 · v0.1.8)가 화면 안에서 하던 일을 탭이 화면 밖에서 이어받는 것이 이 사이클이다. 질문 1 답(2026-09-06)으로 "현재 활성화된 세션"은 화면에서 클릭한 세션이 아니라 가장 최근에 활동한 세션(목록 맨 위)이다 — 다른 세션을 보고 있어도 탭은 실제로 일하는 세션을 따라간다. 질문 3 답(2026-09-06)으로 사용자가 제안된 아이디어 네 개(broke 깜빡임 · 탭 제목 TTL 카운트다운 · favicon 빨간 점 배지 · 브라우저 데스크톱 알림)를 모두 범위에 넣었다. 질문 4 답(2026-09-06)으로 육안 검증 브라우저는 Chrome / Edge다.

### 2.2 제외

- 서버(`server.js`) 변경 — 재료(`charState` · `lastCallStart` · `ttlMin` · 세션 정렬)가 이미 `/events`에 실려 있다(F-3 · F-5). 브라우저가 자동으로 요청하는 `/favicon.ico`의 404(F-1)도 `<link rel="icon">`을 두면 요청 자체가 사라지므로 라우트를 더하지 않는다.
- 전용 favicon 이미지 제작 — 사용자 문장대로 축소만 해서 먼저 본다(SC-2). 안 읽히면 이 사이클에서 그리지 않고 report §3.1로 이월한다(R-1). 설계가 그림의 얼굴 부분만 잘라 키우는 우회를 고를 수는 있다.
- 캐릭터 상태 추가 · 판정 조건 변경 · `LINES` 대사 문구 수정 — `character-spec.md`와 v0.1.5의 영역이다. 탭은 카드가 쓰는 상태와 대사를 그대로 읽는다.
- 캐릭터 카드가 그리는 세션을 가장 최근 활동 세션으로 바꾸는 것 — 카드는 지금처럼 화면에서 선택한 세션을 그린다. 질문 1 답은 탭에만 해당한다(F-5 · R-3).
- `working` 진입(idle→working) 알림 · 깜빡임 — 사용자가 일을 시켰으니 아는 상태다. 사용자 문장이 "일을 마쳤을 때"로 한정한다.
- 소리 · 진동 — 데스크톱 알림이 브라우저 기본 소리를 내는 것까지만이고 페이지가 소리를 재생하지 않는다.
- Safari · 폰 브라우저(브릿지) 지원 — 질문 4 답으로 Chrome / Edge만 육안 대상이다. Safari의 동적 favicon 미지원, 모바일의 탭 아이콘 · 깜빡임 미표시는 고치지 않는다(R-5).
- PWA 매니페스트 · 서비스 워커 · 서버 푸시 — 탭이 열려 있을 때의 일만 다룬다. 탭을 닫아도 오는 알림은 다른 사이클이다.
- 표시 정합성 묶음(3a1e2df9 · 36a5e2bc · 5fcab11d · db0fad38) · 브릿지 재접속 원인 분류(8d12b274) · 죽은 코드 정리(`scoreCard` · `heroCard` · `.stats` · `table.tools` · `.tb`) — v0.1.8 report §7 후보. 다른 사이클.
- 아이콘 폰트 · 알림 라이브러리 · 빌드 도구 — RULE.md 예외 1. 캔버스 합성과 Notification은 브라우저 내장이다.

| FR-1 | 탭(제목 · favicon · 깜빡임 · 알림)은 스냅샷의 가장 최근 활동 세션(`sessions[0]`)을 따른다. 화면에서 선택한 세션과 달라도 그렇다. | 전체 | 필수 |

| FR-3 | 탭 제목은 그 세션의 말풍선 대사(`LINES[charState]`)다. `cc-monitor`라는 글자는 세션이 있을 때 제목에 들어가지 않는다. | 2 | 필수 |
| FR-4 | 캐시가 살아 있으면(TTL 미만료) 제목 뒤에 남은 시간이 `mm:ss`로 붙고 1초마다 줄어든다. 만료 뒤에는 붙지 않는다. `working` · `asking` 중에 붙일지는 설계가 정한다. | 4 | 필수 |
| FR-5 | 같은 세션이 `working`에서 `working` 아닌 상태로 넘어가거나 어느 상태에서든 `broke`로 들어가면 탭이 깜빡인다. 깜빡임은 제목 교대로 하며, 사용자가 탭을 보는 순간(탭이 보이게 되거나 창이 포커스를 받으면) 멈추고 제목이 원래대로 돌아온다. 탭이 이미 보이는 중에 일어난 전이와 페이지를 처음 열었을 때는 깜빡이지 않는다. 전이 비교는 세션 id별이라 맨 위 세션이 다른 세션으로 바뀐 것은 전이가 아니다. | 3 | 필수 |
| FR-6 | `asking` · `broke`일 때 favicon의 캐릭터 그림 한 구석에 빨간 점이 얹힌다. 합성에 실패하면 점 없는 원본을 쓴다. | 5 | 권장 |
| FR-7 | 탭이 보이지 않을 때 같은 세션이 `working`에서 `asking`으로 넘어가면 데스크톱 알림이 뜨고 대사와 세션 제목을 담는다. 알림을 클릭하면 탭이 앞으로 온다. 권한은 화면의 클릭 한 번으로 청하고, 거부됐거나 지원하지 않으면 알림 없이 나머지가 그대로 동작한다. | 6 | 권장 |
| FR-8 | 서버 · 의존성 · 이미지 파일을 바꾸지 않는다. 변경은 `index.html` 하나다. | 전체 | 필수 |
| FR-9 | 세션이 하나도 없으면 제목은 `cc-monitor`, favicon은 `idle.png`다. | 1 · 2 | 필수 |
| FR-10 | README에 탭이 보여주는 것(아이콘 · 제목 · 깜빡임)과 알림 권한을 켜는 법이 한 문단 들어간다. | 전체 | 필수 |

## 5. 성공 기준

| ID | 기준 | 검증 수단 | 관련 FR |
|---|---|---|---|
| SC-1 | Chrome 또는 Edge에서 대시보드를 열면 탭 아이콘이 가장 최근 활동 세션의 캐릭터 그림이고, 다른 세션을 클릭해 카드가 바뀌어도 탭 아이콘은 바뀌지 않는다. | 사용자 육안 | FR-1 · FR-2 |
| SC-2 | 16px 탭 아이콘에서 `working`(안전모)과 `idle`(손 인사)이 구분된다. 구분되지 않으면 그 사실을 do §3에 적고 R-1로 간다. | 사용자 육안 | FR-2 |
| SC-3 | 클로드에게 일을 시키면 몇 초 안에 탭 아이콘이 `working`으로, 일을 마치면 `idle`(또는 `full` · `sleepy`)로 바뀐다. | 사용자 육안 | FR-2 |
| SC-4 | 탭 제목이 카드 말풍선과 같은 문장(`작업 중…` · `대기 중` 등)이고 `cc-monitor`가 보이지 않는다. | 사용자 육안 | FR-3 |
| SC-5 | 캐시가 살아 있을 때 제목 뒤에 `mm:ss`가 붙어 1초마다 줄고, 그 값이 Cache TTL 카드의 숫자와 같은 세션이면 같다. 만료 뒤에는 사라진다. | 사용자 육안 | FR-4 |
| SC-6 | 다른 탭을 보는 중에 클로드가 일을 마치면 탭 제목이 교대로 바뀌며 깜빡이고, 그 탭을 클릭하면 멈추고 대사로 돌아온다. | 사용자 육안 | FR-5 |
| SC-7 | 다른 탭을 보는 중에 클로드가 `AskUserQuestion`을 띄우면(working→asking) 탭이 깜빡인다. | 사용자 육안 | FR-5 |
| SC-8 | 다른 탭을 보는 중에 피할 수 있던 캐시 깨짐이 나면(`broke`) 탭이 깜빡인다. | 사용자 육안 | FR-5 |
| SC-9 | 대시보드 탭을 보고 있는 중에 일이 끝나면 깜빡이지 않는다. 페이지를 새로 고쳐도 깜빡이지 않는다. | 사용자 육안 | FR-5 |
| SC-10 | 두 세션이 번갈아 호출해 목록 맨 위가 바뀌어도, 어느 세션도 `working`을 벗어나지 않았으면 깜빡이지 않는다. | 사용자 육안 | FR-5 |
| SC-11 | `asking` · `broke`에서 탭 아이콘 구석에 빨간 점이 보이고, 다른 상태에서는 없다. | 사용자 육안 | FR-6 |
| SC-12 | 화면의 클릭 한 번으로 브라우저 알림 권한 창이 뜨고, 허용한 뒤 다른 탭을 보는 중에 working→asking이 일어나면 데스크톱 알림이 뜬다. 알림을 클릭하면 대시보드 탭이 앞으로 온다. 권한을 거부하면 알림만 없고 나머지가 그대로다. | 사용자 육안 | FR-7 |
| SC-13 | 세션이 없는 빈 폴더로 서버를 띄우면 제목이 `cc-monitor`, 아이콘이 `idle`이고 콘솔 오류가 없다. | 사용자 육안 | FR-9 |
| SC-14 | `node --test`가 develop과 같은 수로 통과한다. `server.js` diff가 없다. | 자동 테스트 · 로그·수치 | FR-8 |
| SC-15 | 서버 기동 뒤 브라우저가 `/favicon.ico`를 요청하지 않는다(서버 404가 남지 않는다). | 로그·수치 | FR-2 |
| SC-16 | README에 탭 · 알림 문단이 있다. | 사용자 육안 | FR-10 |

SC-1 ~ SC-13 · SC-16이 사용자 육안이다. 탭 · favicon · 알림은 브라우저 안에서만 확인할 수 있고 `index.html`을 여는 자동 테스트가 없어서(F-10) 그렇다. 육안 확인 브라우저는 Chrome 또는 Edge이고, 확인한 날짜와 브라우저 · 포트를 do §3에 남긴다. SC-6 ~ SC-8 · SC-12는 실제 클로드 세션을 한 번씩 돌려야 재현된다.

# Cache Monitor for Claude Code

Claude Code 트랜스크립트(`~/.claude/projects/**/*.jsonl`)를 실시간으로 지켜보는 계기판.
입력은 없고 모니터링만 한다. 형은 계속 VS Code/터미널에서 치고, 이 창은 옆 모니터에 띄워둔다.

- 캐시 TTL 카운트다운, 깨뜨리면 얼마인지
- 컨텍스트 크기와 구성(시스템/내 프롬프트/툴 결과/리마인더…) 톱니 그래프
- 세션 비용
- 압축 추천(폐기물, 손익분기)
- 연비(시간당 비용): 이 세션 · 오늘 · 이 기기를 나란히 비교
- 캐시를 깨는 나쁜 습관 순위 (이 세션 / 폴더 전체)
- 상태 8개짜리 캐릭터

의존성 없음. **Node 18 이상**만 있으면 된다.

## 파일

| 파일 | 역할 |
|---|---|
| `server.js` | 폴더 watch + 증분 파싱 + SSE 서버 |
| `index.html` | 화면 (요청마다 읽으므로 수정 후 새로고침만 하면 됨) |
| `start-monitor.cmd` | Windows 실행 |
| `start-monitor.sh` | Linux/macOS 실행 |
| `character-spec.md` | 캐릭터 상태 정의 + 제미나이 프롬프트 |
| `img/*.png` | 캐릭터 이미지 (512px, 투명) |
| `scripts/diag-breaks.js` | 브레이크 원인별 집계 + 최근 N건 덤프 |
| `scripts/diag-shrink.js` | 브레이크 구간 사이의 원본 레코드 덤프 |
| `test/` | 판정 테스트와 합성 픽스처 |

진단 스크립트 둘은 `server.js`의 판정을 그대로 불러 쓴다. 판정 로직을 복제하지 않으므로 서버가 바뀌면 자동으로 따라간다.

```
node scripts/diag-breaks.js --dir <경로> [--top 20]
node scripts/diag-shrink.js --dir <경로> [--min 2000] [--session <id 접두>] [--cause <원인>]
```

## Windows

```
start-monitor.cmd
```

기본값은 `%USERPROFILE%\.claude\projects`, 포트 7777. 브라우저가 자동으로 열린다.
다른 폴더나 포트:

```
start-monitor.cmd "D:\some\projects" 7780
```

## Ubuntu (Lightsail 등 서버)

```bash
chmod +x start-monitor.sh
./start-monitor.sh                 # ~/.claude/projects, 포트 7777
./start-monitor.sh ~/other 7780    # 폴더, 포트 지정
```

서버에는 브라우저가 없으니 **로컬 PC에서 SSH 포트 포워딩**으로 본다:

```bash
ssh -L 7777:localhost:7777 ubuntu@<lightsail-ip>
```

그 다음 로컬 브라우저에서 `http://localhost:7777`.
서버는 localhost에만 바인딩되므로 외부에 노출되지 않는다.

백그라운드로 계속 띄워두려면:

```bash
nohup node ~/cc-monitor/server.js > ~/cc-monitor.log 2>&1 &
```

systemd로 등록하려면 `/etc/systemd/system/cc-monitor.service`:

```ini
[Unit]
Description=cc-monitor
After=network.target

[Service]
User=ubuntu
ExecStart=/usr/bin/node /home/ubuntu/cc-monitor/server.js --port 7777
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now cc-monitor
```

Linux에서 `fs.watch` 재귀 감시가 안 되는 Node 버전이면 자동으로 2초 폴링으로 내려간다. 로그에 `polling every 2s`가 찍히면 그 상태.

## 옵션

```
node server.js [--dir <projectsDir>] [--port <port>]
```

## 테스트

```
node --test
```

의존성 없이 Node 내장 `node:test`만 쓴다. 픽스처는 `test/fixtures/*.jsonl`의 합성 트랜스크립트라 개인 경로·프롬프트 본문이 들어 있지 않다.
(`node --test test/`는 Node 24에서 디렉터리 인자를 모듈로 읽으려다 실패한다. 인자 없이 쓰면 `test/` 아래를 알아서 찾는다.)

## 캐시 깨짐 막기 (효과 제일 큰 설정)

bkit 스킬들이 프론트매터에 `effort: medium`을 박아놔서 스킬을 드나들 때마다 effort가 바뀌고 컨텍스트 전체가 다시 써진다.
`~/.claude/settings.json`에 아래를 넣으면 스킬이 effort를 못 덮어쓴다 (`effortLevel` 키는 스킬이 덮어쓰므로 쓰지 말 것).

```json
{
  "env": {
    "CLAUDE_CODE_EFFORT_LEVEL": "high"
  }
}
```

기존 키는 그대로 두고 `env`만 추가. 이미 `env`가 있으면 그 안에 한 줄.
확인: 새 세션에서 `/bkit:pdca`를 쳤을 때 State 띠의 effort가 안 바뀌고 캐릭터가 "아야"를 안 하면 성공.

## 보정값

**시스템 바닥(sys)**은 실측 사다리를 쓴다 — 자기 세션의 콜드스타트 → 같은 프로젝트·MCP 구성의 콜드/웜 실측 → 프로젝트 전체 → 폴더 전체 → 그래도 없으면 기본값(45k) 순으로 8단계를 내려가며 첫 표본을 쓴다. 각 단계에서 콜드가 항상 웜보다 앞선다.

**압축 비용**(요약 20k · 재작성 55k · 다시 읽기 60k)은 폴더와 무관한 **고정 상수**다. 폴더 실측 중앙값(재작성 · 압축 후 컨텍스트 · 압축 실비)은 압축 근거 팝업에 참고용으로만 보이고 계산에는 안 들어간다 — 압축 후 크기가 폴더마다 크게 다르지 않다는 실측 결과라, 정밀도보다 "같은 화면의 같은 숫자를 항상 같은 기준으로 설명할 수 있는 것"을 택했다.

이어가기 손익분기(`continueThreshold`)의 "다시 읽기"는 압축 비용과 별개로 **폴더 실측 중앙값**(`CAL.regrowth`)을 쓴다 — 이름은 같지만 압축 비용의 고정값(60k)과는 다른 숫자다.

## 캐릭터 이미지 추가/교체

1. `character-spec.md`의 공통 프롬프트 + 해당 상태의 표정 문장을 제미나이에 넣어 생성
2. 생성물이 격자 배경을 그려서 주면 `img/`에 넣고 `tools/dechecker.ps1` 실행 (원본은 `img/raw/`로 이동, 512px 투명 PNG로 변환)
3. 없는 상태의 이미지는 `idle.png`로 대체된다

## 숫자 읽을 때

- 달러는 API 정가 환산. 구독제면 사용량 한도 소모 감각으로 볼 것.
- 캐시 깨짐 비용 = 다시 쓴 토큰 × (쓰기 단가 − 읽기 단가). 1시간 캐시 기준 쓰기 2배, 읽기 0.1배(Fable 5.1은 0.025배).
- "다시 쓴 토큰"은 **직전 호출이 실제로 캐시에 남긴 프리픽스** 기준이다. 직전 호출에서 캐시에 못 들어간 꼬리는 손실로 세지 않는다.
- 압축과 브레이크포인트 이동(캐시 기준점이 옮겨지며 조금 다시 쓰는 정상 동작)은 원인별 표에 건수·금액이 보이지만 손실 합계와 연속 무사고 기록에는 넣지 않는다.
- 작업을 재개하며 대화 이력이 파일에 다시 쓰인 구간은 한 번만 센다. 같은 uuid가 두 번 나오면 뒤엣것을 건너뛰므로 대화 수·질문 수·커밋 수·압축 횟수가 부풀지 않는다.
- 브레이크마다 판정 근거(직전·현재 호출의 토큰 구성, 캐시 읽기 증감, 컨텍스트 증감, 간격, 프리픽스 보존 여부, 감지한 이벤트)를 함께 저장한다. 원인 표시가 미덥지 않으면 `curl "localhost:7777/api/detail?id=<sessionId>"`로 확인.
- 세션 안에서는 모델을 바꾸지 않는다는 것이 이 대시보드의 대원칙이다. 모델을 바꾸면 컨텍스트 전체를 다시 써야 하기 때문이다.
- 시스템 바닥(sys) 옆의 "실측(콜드)" · "실측(웜)" · "추정"은 위 보정값 사다리의 어느 칸에서 값을 가져왔는지를 그대로 보여주는 것이다.
- 컨텍스트 구성은 문자 수 비율을 실제 컨텍스트에 맞춰 늘린 추정치. 합계는 정확, 비율은 몇 % 오차.
- 압축은 캐시가 살아있을 때 해야 이득. 만료 후 압축은 그 호출이 전체를 다시 쓴다.
- 만료 후 이어가기 vs 새 세션의 손익분기는 컨텍스트 = 바닥 + 다시 읽기(보정값 절의 폴더 실측 `CAL.regrowth`, 압축 비용의 고정 다시 읽기 60k와는 다른 값). 그 아래면 이어가고(비용 `riskUsd`), 위면 새 세션(비용 `freshCost`)이 싸다 — 두 금액과 차액을 화면에 그대로 보여준다.
- **활성시간**은 모델이 실제로 돌던 시간만 합산한 값이다. 같은 요청(requestId) 그룹의 마지막 호출 시각에서 그 그룹 시작 직전 이벤트 시각을 뺀 값들의 합이고, 사용자가 프롬프트를 고민하거나 도구 결과를 기다리는 시간은 빠진다. 벽시계 경과 시간이 아니다.
- **하루 경계는 KST 05시**다. 새벽 5시 이전 작업은 그날이 아니라 전날 몫으로 잡힌다 — 늦은 밤 작업 흐름이 자정을 넘겨도 하나로 묶이게 하기 위해서다.
- **연비**(Cost 카드 하단 "활성 시간 대비 COST")는 시간당 비용(비용 ÷ 활성시간)을 "이 세션 · 오늘 · 이 기기" 세 줄로 보여준다. 각 줄은 $0~100/h 척도의 가로 트랙과 그 위 원으로 값을, 오른쪽에 $/h · $/min과 활성시간을 적는다. "오늘"은 지금 이 순간이 아니라 **선택한 세션이 실제로 활동한 그 하루**의 폴더 전체 값이고, "이 기기"는 폴더 전체 누적이다. "폴더 전체"는 `--dir`로 지정한 폴더 전체를 뜻하며, 프로젝트 하나만 가리키게 띄웠다면 그 프로젝트가 "폴더 전체"다.
- **오늘 누적**(Cost 카드의 큰 숫자 아래 줄)은 그 하루에 이 폴더 전체가 쓴 금액이다. 바로 위 큰 숫자는 선택한 세션 하나의 총액이라 범위가 다르다. 날짜 기준은 연비의 "오늘"과 같다 — 선택한 세션이 활동한 하루이고 경계는 KST 05시다.
